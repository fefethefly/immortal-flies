# IMMORTAL / Genesis contract prototype

**Status: local MVP + testnet-only path.** This repository includes a compilable ERC-721, Anvil tests, and a BSC testnet (chainId 97) deploy script. A live testnet address appears only after you run `npm run contracts:deploy:testnet`. There is no mainnet deployment, sale, audited security guarantee, or whole fruit-fly brain simulation.

**Do not deploy `ImmortalFly.sol` to BSC mainnet (chainId 56).** It stores a 16-node toy brain, user-chosen seeds, and the prototype NFT symbol `IFP`. Official tax-coin ticker is **`$IFS`** (`public/token/official.json`). Soul identity on testnet is `contracts/life/ImmortalSoul.sol` (`IFSOUL`). See `docs/LIFE-PROTOCOL.md` and `docs/PRODUCT-LATEST.md` §19–§20.

```sh
npm run life:compile
npm run life:test
```

## What the contract preserves

`ImmortalFly.sol` stores every numeric input required to resume `iff-neural-16-v1`, the deterministic 16-node model in `src/engine.mjs`:

- DNA, chain birth timestamp and block, generation, parent token IDs (both zero for Gen0).
- 16 membrane potentials, 3 learned preferences, RNG state, spike bitset.
- Simulation ticks, energy, incarnation number, dormancy.
- An on-chain basic SVG card and metadata renderer, with no external URL.

There is no admin, proxy, upgrade entry point, pause, burn, payable mint, project service fee, or arbitrary state upload. The maximum supply is fixed at 1024. Rebirth changes energy and incarnation while retaining the rest of the brain, without minting a new token. State continuity relies on the deployed chain continuing to exist and its data being accessible; the contract does not run autonomously between transactions.

This MVP implements only Gen0. It does **not** implement breeding, royalty distribution, external storage, opBNB bridging, a token economy, maze scoring or authenticated achievements. Frontend maze records are local experiments and must not be represented as contract-certified results.

## Run locally

Requirements: installed npm dependencies and `anvil` on PATH.

```sh
npm run contracts:compile
npm run contracts:test
npm run contracts:check:testnet
# IFF_DEPLOY_KEY=0x… npm run contracts:deploy:testnet
```

The test script launches its own Anvil node bound only to `127.0.0.1`, chooses an available port, deploys there, exercises the contract, writes a report and terminates the node. It never connects to or deploys on a public chain. An environment that disallows local sockets must grant permission to start this local test process.

Outputs:

- `artifacts/ImmortalFly.json`: full ABI, bytecode, compiler metadata and storage layout.
- `public/contract/ImmortalFly.json`: ABI and bytecode; compile keeps this as `UNDEPLOYED_PROTOTYPE` (no address).
- `public/contract/ImmortalFly.deployment.json`: testnet address, `fromBlock`, explorer URL. Written by the deploy script; compile does not erase it.
- `artifacts/contract-test-report.json`: local test results and measured gas, generated by the test command.

Compilation targets the Paris EVM with Solidity 0.8.30, optimizer 200 runs, via-IR. No newer Cancun-only instructions are required. Compatibility has been tested against local Anvil. Public testnet deploy uses the same Paris / 0.8.30 artifact. See [docs/TESTNET.md](../docs/TESTNET.md).

## Public API

| Method                                          | Meaning                                                                      |
| ----------------------------------------------- | ---------------------------------------------------------------------------- |
| `mint(uint32 seed)`                             | Free prototype mint to caller, seed must be nonzero.                         |
| `getFly(uint256 id)`                            | Read complete identity and brain; no ownership required.                     |
| `tick(uint256 id, uint8 stimulus, uint8 steps)` | Advance 1–128 ticks. Stimuli 0–2 are trained channels; 3 is neutral.         |
| `train(uint256 id, uint8 channel)`              | Increase one preference by 40, capped at 1000, then compute 32 ticks.        |
| `sleep(uint256 id)`                             | Preserve state and set dormancy.                                             |
| `wake(uint256 id)`                              | Resume only if energy is nonzero.                                            |
| `rebirth(uint256 id)`                           | Set energy to 1000, wake, increment incarnation. All learned state persists. |
| `tokenURI(uint256 id)`                          | Base64 JSON containing Base64 SVG and current metadata.                      |

Every state action requires the current owner, the token's approved address, or a globally approved operator. **An approved NFT operator can change the brain**, not just transfer the token. Transfer clears token approval, and the old owner loses mutation permission. This broad permission is appropriate to the requested prototype API; review a separate gameplay delegate role before a production launch.

On-chain ticks pause during dormancy or after energy is exhausted. Transactions cannot inject old checkpoints or fabricated learned parameters. There is no project permission needed to read or independently simulate the public state. Only the authorized controller can advance the canonical state.

## Rebuilding the simulator state

```js
const f = await contract.getFly(tokenId);
const restored = {
  model: await contract.MODEL(),
  id: Number(tokenId),
  dna: Number(f.dna),
  bornAt: new Date(Number(f.bornAt) * 1000).toISOString(),
  brain: {
    rng: Number(f.brain.rng),
    ticks: Number(f.brain.ticks),
    learning: Array.from(f.brain.learning, Number),
    potential: Array.from(f.brain.potential, Number),
    energy: Number(f.brain.energy),
    spikes: Number(f.brain.spikes),
    incarnation: Number(f.brain.incarnation),
    dormant: f.brain.dormant,
  },
  achievements: [], // No achievements are certified by this contract.
};
```

The frontend checkpoint validator currently serves the single local demonstration specimen; extending UI import to other token IDs requires adapting that schema. `bornAt` in the on-chain model comes from the mint block timestamp. Browser `bornAt` is local time and will differ. Compare numeric brain trajectories, not an entire browser checkpoint hash, when checking equivalent simulation results. For extraordinarily large tick counts exceeding JavaScript's safe integer range, retain ticks as bigint in an adapted simulator.

## Distribution and permanence limits

- Seed selection is user-controlled and can produce duplicate DNA. There is no verifiable random rarity or anti-Sybil distribution.
- Anyone can consume the free supply; the contract is not a reviewed sale mechanism.
- No burn entry point means a token cannot be destroyed via the contract. It does not prevent a holder from losing keys or transferring to an inaccessible address.
- Simulation age counts computed ticks. Birth block is not evidence of continuous activity.
- Rebirth is permitted with remaining energy, as in the JS engine. Its count does not increase abilities or a rarity score.
- Public model data can be copied and simulated elsewhere. Canonical ownership and state provenance are defined by the particular deployed contract and chain.
- Any mainnet plan uses a **new** Soul contract, not this file. That plan is written in `docs/PRODUCT-LATEST.md` §19: committed seed, genome hash, decoder id, no on-chain 16-node ticks. Official coin ticker stays `$IFS`; this prototype NFT is `IFP`, not IFS. This prototype still needs explicit testnet configuration, gas numbers, and review before even chain 97.

`contracts/test/MintBatch.sol` is a test-only receiver used to actually mint all 1024 identities and prove the supply boundary; it is not part of the shipped collection artifact.
