# FlySwarm 群体智慧协议：设计稿

日期：2026-09-17。状态：**设计稿，未实现**。产品正文已收录裁定、对象、接口与诚实边界，见 [PRODUCT-LATEST.md](PRODUCT-LATEST.md) §0.3 第 7 条、§4.4、§21。本文仍是实验、schema、Railway 运维与未决参数的细则，不替代产品正文。上游依据：[RUNTIME-TIERS-DESIGN-2026-09-17.md](RUNTIME-TIERS-DESIGN-2026-09-17.md)（三层架构与 dataset 注册表）、[LIFE-PROTOCOL.md](LIFE-PROTOCOL.md)（身份核与模块纪律）、[BRAINWEB-RESEARCH-2026-09-17.md](BRAINWEB-RESEARCH-2026-09-17.md)（竞品口径）。

## 0. 一句话

协议标准化的不是「智慧」，而是五个可验证接口（任务 / 语言 / 学习 / 聚合 / 身份）；「智慧增长」是闭环运转后的涌现结果，协议只负责让每一次增益**可以被任何人复算**。

## 1. 背景与已确认决定

FlySwarm 已有版本化 schema、era 哈希链日志、confidence-hold quorum、mesh/hosting 与行为/金融解耦。缺失两层：**选择**（哪个经验该被保留）与**传播**（语言只表达动作，不表达观察与依据）。

产品负责人 2026-09-17 确认：

1. **母体与初始子生命实例均由官方生成**，官方直接提供。
2. 官方经 **Railway 等外部云服务**部署运行（约束见 §6，未实测云成本）。
3. **开放用户接入**果蝇生命实例（权限边界见 §7，分阶段）。

## 2. 目标与非目标

| 目标 | 非目标 |
| --- | --- |
| 用协同觅食做出「协作增益」「学习泛化」两个可复算证明 | 不保证「只会越来越聪明」；单调提升不是技术承诺 |
| 把演化四步（变异-选择-传播-遗传）做成可验证接口 | 不模拟果蝇真实信息素通信；语言是经验层 |
| 晋升的每条经验附复算包，任何人可独立重放 | 不以持币量、节点数、哈希数量作为智能证据 |
| 母体是老师不是君主：官方实例无豁免票权 | 不做中心化主脑覆盖用户生命的模型 |

## 3. 对象模型

| 对象 | 定义 | 数量关系 |
| --- | --- | --- |
| **GenesisMaster 创世母版** | 数据集 + 初始模型 + 编解码器版本的登记事实，不可暗改 | 每物种谱系一个 |
| **LifeInstance 生命实例** | 独立状态 + 独立经历 + 可学习参数的单个生命（有 soulId） | 智慧的持有单位 |
| **Runner 运行器** | 执行计算的进程（`iff.mesh-node/1`） | 一生命可多运行器；一运行器可多生命 |
| **ComputeNode 计算节点** | 只计算/存储/复核，不构成新个体、不加票权 | 服务器数 ≠ 生命数 ≠ 独立经验数 |
| **Swarm 蝇群** | 共享同一评测域与晋升规则的生命集合 | quorum 成员边界 |

**母体 = GenesisMaster 衍生的第一个官方 LifeInstance，无协议特权。** 初始子实例同样官方生成（不同 seed、观察半径），是第一批多样性来源；用户接入后官方占比逐步稀释，终态是官方只留普查与仲裁。

## 4. 五个接口

```text
① Task     任务接口   确定性评测环境 + 成功判据；环境内容寻址、可审计
② Message  语言接口   观察/提议/确认/结果/候选经验（§5）
③ Learn    学习接口   可评测、可回滚的状态变更；旧版本永不覆盖
④ Pool     聚合接口   Claim → Replication → Promotion（§8）
⑤ Identity 身份接口   lifeId 与 runner 分离；贡献记账；族谱留痕
```

| 生物学机制 | 协议层 | 现状 |
| --- | --- | --- |
| 遗传 | `iff.genome/1` + `iff.genesis/1`，decoderHash 钉死 | ✅ 已有 |
| 表型 | `iff-runtime/1` 整数内核，逐位重放 | ✅ 已核验 |
| 行为 | `iff.utterance/2`（行为/金融解耦） | ✅ 已落地 |
| 群体决策 | `iff.quorum/2` confidence-hold | ✅ 已落地；v3 待读 dataset 注册表 |
| **自然选择** | **§8 晋升规则** | ❌ 新建 |
| **交流传播** | **§5 五动词** | ❌ 半成品（只有动作话语） |

**内核核验记录（2026-09-17 复核，修正此前误判）**：`src/brain/runtime.mjs` 的 `step()` 只推进电位/不应期/身体/暴露量；**学习已存在于产品层**——`src/brain/learn.mjs` 的 `iff.overlay/1`（learner `outcome-gain/1`）按已实现结果缩放感觉增益（`modulate` 注入 `tickColony`），不改 MaleCNS 边权；kernel 已按结果调用 `learner.apply` 更新各 member 的 overlay（`kernel.mjs` §tick 第 1 步）。**缺口是驱动**：`outcomeOf` 只在交易 SELL 已实现盈亏时产生 -1/0/1 反馈——T4 的正确做法是**换驱动（觅食/避险 outcome），不换对象**。

## 5. 语言：映射到已有对象，不另起第三套词典

PRODUCT-LATEST §4 已有 SENSE / ACT / MEMORY / PROPOSE 话语体系；schemas.mjs 已登记 `iff.sense/1`、`iff.experience/1`。本协议的五个动词是**补依据与验证**，必须映射到旧对象：

| 本协议动词 | 对应已有对象 | 做法 |
| --- | --- | --- |
| observe | `iff.sense/1` | 升 **sense/2**（新版本，不改 /1）：加 envId / region / evidence{输入承诺,种子} |
| propose | 产品层 PROPOSE | 可新增记录，**必须引用 observe**，且不自动执行 |
| confirm | 无 | **值得新增**——独立复核，是复现的最小形态 |
| outcome | overlay 的结果事件 | 独立事件记录，**不塞进 utterance**（行为/金融解耦纪律不变） |
| claim | `iff.experience/1` 是记忆根，**不是晋升申请** | 新增 claim 记录，引用 experience + 复算包 |

每条消息强制携带：来源标识（见 §5.1 身份字段对照）、model/adapter 版本、envId、逻辑时间（tick，禁 Date.now()）、单位与参照系。**未知 schema 大声拒绝；收到 ≠ 服从**。跨物种预留不变：语义经各物种 decoder 映射到公共消息层，不共享神经元编号/电位/奖励信号。

### 5.1 身份字段对照表（S1 冻结 schema 前必须先定）

现有记录主键是 soulId；链上 lifeId 是 `chainId + collection + tokenId` 的哈希（LIFE-PROTOCOL §1）。官方启动期实例**未铸 Soul**，若直接登记 `observerLifeId` 只能造假身份或返工 schema：

| 字段 | 含义 | 官方未铸实例的取值 |
| --- | --- | --- |
| instanceId | 带命名空间的本地实例标识 | `sim:official-mother` 等，消息主键用这个 |
| soulId | 内核名册主键（可本地生成） | 内部用，不对外冒充链上身份 |
| lifeId | 链上身份 | **空，直到真正铸造** |
| runnerPub | 执行运行器（`iff.mesh-node/1`） | `paper:` 或真实公钥 |
| session | 单次运行会话（controlEpoch 语义） | 会话绑定与授权检查用 |

### 5.2 T3 入站适配器与因果边界（设计，未实现）

按版本固定 `receive(messages, receiverState, taskContext, budget) → acceptedInputs + receipts`。检查发送会话、目标生命、环境/坐标系、序号、重复、过期、大小和通信预算；仅使用发送者实际观察得到的信息，不能泄漏评测器全局真值。消息按规定顺序投递到下一逻辑拍，不建立同拍递归反馈。输入与拒绝回执均记录消息引用、接收 tick、适配器版本、拒绝原因与消耗预算，以支持重放和消息打乱/移除实验。

观察事实与感觉注入不是同一对象。`iff.sense/1` 当前是含 food/threat/light 的输入帧；sense/2 是否同时承载观察证据，须由 Task/T3 实际字段决定，不能只加坐标就宣称语义完备。propose 是候选建议，不直接写动作；由有版本的接收策略决定是否转换为输入。适配器固定，不暗中成为知道最优解的控制器；需加入适配器+简单非神经策略对照以分辨增益来源。

T2 可复用 quorum v2 的行为分布函数，但它不是通用广播或觅食控制器；任务输出适配需另定并对所有组公平。T3 的新增部分是成员间入站通信，不替换经验晋升 Pool，也不把 Mesh 当通信或学习的实现证明。是否使用 quorum 作为团队动作头取决于任务，并在 T2/T3 间保持一致。

## 6. 启动拓扑：官方生成、官方 Railway 托管

**已确认**：母体和初始子生命实例均由官方生成，部署目标为 Railway，开放用户接入。以下具体数量、服务拆分和接入阶段为建议，不代表用户已批准付费、铸造或部署操作。

```text
官方创世母版（版本固定、可复原）
  ├─ 母体生命实例：malecns-full，独立状态
  └─ 初始子生命实例 ×N：独立状态、经历与实例身份
         ↑ 官方生成并在 Railway 托管
         ↓ 会话授权、输入队列、观察/结果消息
用户客户端 → 接入网关 → 运行器 → 日志/检查点存储
                            ↓
                   隔离评测 → 候选知识/模型版本
```

- 建议从母体 + 2 个子实例启动；为了先检验“多个大图实例如何协作”，初始子实例优先采用同一 `malecns-full` 模型配置，是否满足并发预算须云端压测。1,400 子图可作开发对照及后续混合规模实验，不是已确认的子实例限制。
- 各生命可以共享同进程的只读图，但必须有独立状态、种子、输入游标与日志。不同进程/副本不自动共享图内存。同创世不代表经历完全相同，换种子也不保证有足够多样性。
- 用独立的模型继承记录引用母版版本及来源检查点；**不得因复制模型就填写 `parentSouls`、提高 generation 或制造链上亲子事实**。繁衍遵守 LIFE-PROTOCOL 的独立规则。未绑定 NFT 的实例使用带命名空间的本地 instanceId，不冒充链上 lifeId。
- 初期中央服务掌握运行和发布权限，应披露为“官方托管实验网络”。官方实例互相验证属于同一运营方的内部重复实验，不是第三方独立复现。
- 云部署不自动等于 TESTNET：纯模拟保持 `audit=SIM`；实际涉及测试链的事件才标 TESTNET。链环境标签不表示科学验证等级。

### Railway 部署要求（尚未部署）

1. 固定运行器、图、metadata、输入输出适配器及任务版本。预处理图是本项目产物，不假定 Janelia 原始下载地址直接提供同哈希文件；从已发布的可信版本制品源获取并逐项验证，保留来源与许可。
2. 建议网关、运行 worker、评测 worker 逻辑隔离；可先少量服务部署，再依据性能拆分。每个实例单写者，故障接管需租约/epoch fencing，过期执行者不能继续提交状态。
3. 临时容器磁盘不作唯一档案。采用持久卷或对象存储保存检查点和追加日志，定义保留期、备份与恢复目标；下载制品不等于已解决状态持久化。
4. 发布健康检查和就绪检查；图校验与检查点恢复完成后才接纳输入。停止时记录最终已提交 tick，恢复时重放已接纳事件并去重。
5. 测加载、逐步与批步耗时、p95、运行 RSS 峰值、并发、存储增长和断线恢复。费用按实际套餐及 CPU/内存/流量/存储核算，不承诺固定月费。
6. 不在客户端或公开日志放运营密钥。不创建云资源、不购买套餐、不自动部署主网合约；这些属于后续实施。

## 7. 用户接入与权限

建议先开放只读观察，再开放**用户接入官方提供的子生命实例**：用户不必先租服务器。后续才开放携带兼容生命档案或自托管 runner 接入。计费、认领与所有权转移规则另行确认，本设计不强制付费或质押。

| 操作 | 授权与边界 |
| --- | --- |
| 观察 | 读取已公开的状态摘要、话语流、评测报告与复算包 |
| 接入子实例 | 会话绑定 user/instance/能力范围/有效期；接入权不自动是 NFT 所有权 |
| 施加环境输入 | 经输入适配器、范围校验、限速、队列和日志接纳；不是伪造生命的 utterance 输出 |
| 发布观察/提议 | 绑定生命及运行会话，校验来源、序号与上下文；收到消息不等于获得控制权 |
| 升级/恢复模型 | 经实例控制者授权，记录旧/新版本与迁移事件，可恢复旧检查点 |
| 自托管 | 后续通过兼容性、授权及恢复检查；多开 runner 不增加同一生命的票数 |

同一生命在任一控制 epoch 只有一个权威写入会话；多用户共享互动若开放，必须经确定性队列排序，不让多个控制者直接覆盖状态。解绑、过期、撤权后拒绝旧令牌；NFT 绑定实例遵循已有 `authorizedRunner`/`controlEpoch` 语义，不修改身份核。

官方母体默认只读，实验输入由任务控制器接纳。用户不能直接改母体或别人的模型；正式评测期间禁外部任意刺激，以免污染对照。

## 8. 经验验证、模型学习与晋升

**先分清三件不同的事**（本稿此前混称「聚合」，自洽性修正）：

| 层 | 现有实现 | 本协议新增 |
| --- | --- | --- |
| **Quorum 行为聚合** | `kernel.mjs` 每 tick 跑 confidence-hold/2 行为压池 → 群体动作 | 不动；T2 直接复用 quorum v2，不为它加 schema |
| **Pool 经验晋升** | 无 | §8.1 的状态机——晋升的是「经验/模型版本」，不是每 tick 行为 |
| **Mesh 分片托管** | `iff.mesh/1` + `iff.hosting/1`（官方图分片租算力） | 不动。**mesh ≠ 群体智慧**，对外分开讲 |

### 8.1 三种证据必须分开

- **执行重复性**：同代码/输入重放得同结果，只证明该计算可重复。
- **任务增益**：候选比基线在未见条件下表现更好，须评测与统计支持。
- **独立复现**：不同实际运营控制方复核完整实验；不同钱包、runner、region 并不证明独立。身份去重与独立性证据仍需治理设计，不能靠 K 次计数解决女巫问题。

经验状态建议为 `CANDIDATE → INTERNALLY_VALIDATED → EXTERNALLY_REPLICATED → PROMOTED`，另有 `DISPUTED`、`REVOKED`。官方启动期可形成内部验证版本供可选实验，但不得冒充外部复现；没有第三方不阻塞内部学习。

晋升不仅要求复现数：还需完整复算包、冻结的基线与任务、预登记增益门槛、回归检查、争议处理和明确发布者。K、独立性判据、窗口及发布权限均版本化，具体参数待定。撤销写入独立评测历史，不改生命的出生族谱。

### 8.2 Learn：走 overlay 既有缝，不另起炉灶

`learn.mjs` 已写明「不改 MaleCNS 边权」；kernel 已按结果更新 overlay（`iff.overlay/1`，learner `outcome-gain/1`），**只是驱动绑了交易 PnL**（`outcomeOf` 仅在 SELL 已实现盈亏时给 -1/0/1）。T4 的正确做法是**换驱动（觅食/避险 outcome），不换对象**：

- 新 learner 注册为 registry 新条目（如 `outcome-forage/1`），复用 `modulate` 注入路径；
- 候选记录含：baseModelHash、learnerId/version、训练域/预算、更新工件哈希（overlay 快照）、评测引用、适用模型、恢复检查点；
- 流程不变：训练域更新 → 冻结候选 → 无更新模式评测 → 内部批准可选版本 → 外部复现晋升；
- 不强制同步升级，旧版本与多样分支保留；外部策略提升不得归因为突触学习；
- 第一版**不改**连接组数据、不动 `outcome-gain/1` 旧语义（交易驱动保留在交易场）。

### 8.3 盲测、复算与持久化

先承诺候选及评测规则，再生成或由隔离评测方保管未用于训练的测试条件；测试完成后公开种子和输入供重放。候选冻结前可见的区块哈希不是盲测保障，区块哈希本身也可能被影响。首版可使用官方隔离留出集并披露信任局限，不依赖随机性上链。

复算包至少含：任务/图/模型/适配器工件、基线、初始状态、种子、完整输入、通信日志、评测代码、预算及结果。评测所必需的状态不能一面隐藏一面声称可复算。哈希是完整性承诺，不是计算正确或数据可用的证明；存储与保留责任需明确。未来锚定链上使用可替换模块，不重部署 Soul 身份核。

## 9. T0–T4 实验验收

环境采用项目定义的虚拟觅食与威胁规避；food/threat/light 映射是工程模型，不宣称复刻完整生物感觉回路。

| 层 | 配置 | 目的 |
| --- | --- | --- |
| T0 | 单生命，冻结模型 | 测单体基线，不预设得分 |
| T1 | N 生命不通信 | 控制并行搜索收益，成绩可以高于或低于 T0 |
| T2 | N 生命简单广播/聚合 | 控制简单信息共享收益，禁止预设其失败 |
| T3 | 相同 N、模型、感知布局，协议通信协作 | 与 T1/T2 比较协议协作增益 |
| T4 | T3 加训练域学习，冻结后评测 | 与 T3 比较留出环境上的学习增益 |

预登记同一团队目标（例如固定时域内采集量）、成功判据、资源分配和至少一个安全指标。T1–T3 使用配对环境种子、相同个体观察权限、动作预算及通信预算（T1 为关闭通信）；T0 用可比较的总预算，另报不同预算下性能曲线。记录 CPU 时间/硬件、神经元更新、实际边处理量、训练开销、通信字节、延迟及存储；不同模型不能仅按 tick 数宣称算力相同。

试点建议至少 100 个独立环境种子，最终样本量由先导方差及预设最小有意义增益 δ 决定。报告配对差异、95% 置信区间、失败率、多比较处理及全部种子结果。晋升门槛在测试前固定：主要指标差异的区间下界超过 δ，安全指标不越预定退化容忍线；不达标就记录失败，不改指标追逐显著性。

T3 要与 T1 和有竞争力的 T2 比较，并加入消息打乱/移除的消融实验。T4 增加清除学习状态、禁止更新及新环境测试，报告训练成本。只在证据支持时声称“在任务/预算/版本条件下有协作或学习增益”，不推广为通用智慧已实现。
