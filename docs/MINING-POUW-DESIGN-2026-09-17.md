# 挖矿机制设计：蝇群神经元网络节点 + IFS + NFT（PoUW）

日期：2026-09-17。状态：**架构起源稿，未实现；现行规格以 [蜂巢验证网络设计](MINING-HIVE-VERIFY-DESIGN-2026-09-17.md) 为准，本文 §12 记录同日勘误**。本文提出一套「有用工作量证明（Proof of Useful Work，PoUW）」挖矿机制，把三类对象各归其位：**蝇群神经元网络节点 = 工作量本体，IFS = 座位抵押与奖励结算资产，NFT = 矿工身份与矿位执照**。上游依据：[PRODUCT-LATEST.md](PRODUCT-LATEST.md)（§6 Credit、§8 金融飞轮、§15 托管网、§21 群体智慧协议、§22 繁衍费）、[LIFE-PROTOCOL.md](LIFE-PROTOCOL.md)（身份核与卫星纪律）、[RUNTIME-TIERS-DESIGN-2026-09-17.md](RUNTIME-TIERS-DESIGN-2026-09-17.md)（三层运行与 dataset 注册表）、[SWARM-INTELLIGENCE-PROTOCOL-DESIGN-2026-09-17.md](SWARM-INTELLIGENCE-PROTOCOL-DESIGN-2026-09-17.md)（五个接口与 T0–T4）。

本文任何内容不构成收益承诺。未决参数以「建议值」标注，不写入产品承诺。

## 0. 一句话

**矿 = 可复算的蝇脑工作量。** 矿工不是烧电猜哈希，而是运行 / 复核 / 托管蝇群神经元网络的确定性 tick；每份工作量都附复算包，任何人可独立重放验证。IFS 是结算与座位抵押资产，Soul NFT 是矿工身份，Position NFT 是矿位执照；奖励只来自协议生态预算，不增发、不欠账、不以节点数当智能证据。

## 1. 为什么是 PoUW 而不是 PoW

| PoW 哈希挖矿 | 本设计 PoUW |
| --- | --- |
| 工作量 = 猜 nonce，无外部价值 | 工作量 = 官方 era 日志复现、冻结候选隔离评测、mesh 分片托管，全部是协议真实需要的计算 |
| 算力证明不可复用 | 每份回执都是可下载、可重放的证据，服务于 §21 的「独立复现」目标 |
| 多买矿机 = 多收益，必然中心化 | 座位绑 Soul、每座位每纪元份额封顶（对齐 `voteCapPerRunner` 纪律） |
| 增发奖励 → 通胀 | IFS 总供应固定（1e27），奖励出自协议 D 拨定的生态任务桶，桶空即停机（奖励为零，不借未来） |

挖矿是**群体智慧协议的激励层，不是第二套协议**：§21 定义了观察 / 确认 / 评测 / claim 的验证经济，但没给激励；本设计补的就是这一层，所有对象映射到已有 schema，不另起词典。

## 2. 三件套各归其位

### 2.1 蝇群神经元网络节点 → 工作量本体

节点必须真实运行 MaleCNS 内核（`src/brain/runtime.mjs` 整数化 LIF，逐位重放已核验）。按 dataset 注册表分级（RUNTIME-TIERS §5）：

| 节点档位 | dataset id | 可领工作 | 说明 |
| --- | --- | --- | --- |
| 浏览器子图 | `malecns-circuit`（12,000 节点 / 477,021 边 / 3.86 MB） | W1 复现、W2 轻量评测 | 人人可玩，零成本 |
| 社区全量 | `malecns-full`（161,839 节点） | W1/W2/W3 全量 | 22.6 MB 图，活跃脑单步 p50≈25 ms，1GB 内存档可行 |
| 官方运行器 | `malecns-full` 官方实例 | 产出 era 日志头哈希（被复现方） | 官方是种子不是特权，无挖矿豁免（§21.3） |

节点 ≠ 神经元所有权：成为网络的一部分 = 托管官方图的一片 / 复核官方日志，**不是给自己写一个新神经元**（RUNTIME-TIERS §8.2）。首页 atlas 不得把矿工节点数写成「群体智能已实现」。

### 2.2 IFS → 抵押 + 结算 + 罚没，三用合一

- **座位抵押**：领取任务的座位必须占用已有 `iff.stake/1` 质押（`occupyCredit(purpose="mining")`），同一笔抵押只支撑一个座位（Credit 纪律：同一抵押只支撑一次额度）。
- **奖励结算**：纪元奖励只以 IFS 发放，来自 `PROTOCOL_POLICY.ecosystemBps`（D 的 10% 生态任务桶）下的 `miningBudget` 子池。池有余额才发；无 D 或停机时纪元预算为零，挖矿收益自然为零——不印钞、不借款、不承诺收益率。
- **罚没**：错误结果 / 争议败诉罚没部分 IFS 占用，进已公布蜂巢 `0xfAdb2FE136c89866Cd1CB0DD31298e08cc61a467`，单独记账为「罚没」，**禁止写成销毁或回购**（§18 纪律）。
- **BNB 只作轨道**：gas 与算力费用，不授予 bonded，不进入 Life Core（§15）。

### 2.3 NFT → 三层身份，不制造假稀缺

| 层 | NFT 类型 | 语义 | 何时做 |
| --- | --- | --- | --- |
| 矿工身份 | **Soul NFT**（已有，`ImmortalSoul` 主网 LIVE） | 谁在挖：座位主键 `lifeId = chainId + collection + tokenId` 哈希。一地址一生一孵 Gen0 天然挡住第一层女巫 | 已有，零改动 |
| 矿位执照 | **Position NFT**（§7.2 已预告的 NFT 三类之一） | 一只蝇的「蜂巢工位」：可转让执照，转移清空 `authorizedRunner` 并 `++controlEpoch`（沿用既有语义）。买执照 ≠ 买对方正在跑的脑会话 | M3 再议，v1 用卫星合约记录座位，不铸新 NFT |
| 证明工件 | **History NFT**（§7.2 三类之一） | 晋升经验的纪念性证明工件：指向复算包与晋升记录，**无收益权、无地板价、无稀有级** | M4 再议；禁止在 T3/T4 通过前宣称它代表「智能」 |

纪律：NFT 不写进 `ImmortalSoul`，全部是卫星（`lifeId` / `tokenId` 主键）；新 NFT 的稀有级、名次、价格字段一律禁止（LIFE-PROTOCOL §8）。「为 NFT 而 NFT」不是目标——v1 挖矿完全可以在 Soul + 卫星座位合约上跑通。

## 3. 对象模型与新 schema

全部沿用 `iff.*` 版本化纪律；未知 schema 大声拒绝；旧版本保留可重放。

| 对象 | schema（建议） | 内容 | 与已有对象的关系 |
| --- | --- | --- | --- |
| 矿位 MiningSeat | `iff.seat/1` | lifeId（或官方未铸实例的 `instanceId`，仿 §21.5 身份对照表）、Position NFT 引用、运行器授权、占用质押引用、状态（idle / working / disputed / held） | 一只蝇一个矿位；多运行器不增加份额 |
| 工作单元 WorkUnit | `iff.work/1` | task 内容寻址引用（dataset / runtime / 冻结基线与种子 / 输入承诺）、配额、预算、纪元 | task manifest 复用 `iff.dataset/1` + §21 Task 接口的 manifest |
| 工作回执 WorkReceipt | `iff.work-receipt/1` | workUnit 引用、输出哈希、证据引用、评分、奖励记账、复核引用 | claim 的新形态：引用 experience + 复算包（§21.4 ④） |
| 纪元预算 MiningEra | `iff.mining-era/1` | era 头哈希（复用 era 分片日志）、预算 B_e、任务目录、结算摘要 | 复用 `log.mjs` era 哈希链，不另建链 |
| 复核抽签 | （无新 schema） | `keccak(eraHead, seatId, taskId)` 确定性指派复核人 | 抽签结果任何人可复算；防自选任务刷分 |

链上形态：独立卫星合约 `MiningHub`（同 SoulMarket 纪律：**不进 `modules[]`**，不 `mintDescendant`、不写 Soul）。链上只存承诺哈希与结算记录；全量状态、复算包、日志存链下，公开下载独立重放（§20.3 分工不变）。

## 4. 三种工作量（W1 / W2 / W3）

| 类 | 名称 | 干什么 | 验证方式 | 对应协议目标 |
| --- | --- | --- | --- | --- |
| W1 | **复现（confirm）** | 下载官方 era 日志 → 本地重放 → 比对头哈希 → 提交 confirm 回执 | 哈希比对 + 随机抽查复核 | §21 「独立复现」的最低形态；数据可用性 |
| W2 | **隔离评测（evaluation）** | 领取任务注册表里的冻结候选 + 留出集 → 运行 → 提交结果，与预登记阈值比对 | 结果在预登记区间内才有效；复算包可重放 | T0–T4 的评测容量；盲测纪律（§8.3） |
| W3 | **分片托管（hosting）** | 挂 `iff.mesh-node/1` 分片，心跳 + 随机读取挑战（challenge-response） | 心跳连续性与挑战应答正确率 | §15 mesh 算力外摆；D5 社区接管 |

奖励权重建议 `w1 : w2 : w3 = 4 : 4 : 2`（版本化参数；S6 后按实测调整）。**三种证据必须分开**（§21.6）：执行重复性 ≠ 任务增益 ≠ 独立复现——回执上三列分写，禁止用「执行了 N tick」冒充「验证了智能增益」。

## 5. 一个纪元的工作流（era 对齐 era 分片日志）

```text
纪元开始：era 头哈希冻结 + 预算 B_e 公布 + 任务目录冻结
    │
① 领单    座位状态 idle → working；任务按 keccak(eraHead, seatId, taskId)
         确定性指派（防自选）；每座位每纪元任务配额封顶
    │
② 执行    跑 MaleCNS 内核 tick；产出状态哈希 + 证据（W3 为心跳/挑战应答）
    │
③ 提交    WorkReceipt 上链（承诺哈希）；全量证据链下可下载
    │
④ 复核    其他座位按抽签复核 W1 结果（复核本身计 W1 分，复现者封顶防共谋）
    │
⑤ 结算    按 §6 公式分配 B_e；违规者罚没（§7）；回执入 era 日志
    │
⑥ 纪元尾  未领完的预算滚回准备金或下一纪元，不印钞、不追溯分配
```

每个纪元固定预算、固定任务目录、预登记判据（对齐 §21 的「预登记」纪律）：**测试完成后再公开种子与输入**；晋升门槛在测试前固定，不达标记失败，不改指标追显著性。

## 6. 奖励与预算

### 6.1 预算来源（关键：零增发）

```text
B_e = min( miningBudget 池余额, eraBudgetCap × 递减系数(e) )
miningBudget ⊂ D 的生态任务桶（ecosystemBps = 1000，PROTOCOL_POLICY 已有）
```

- 停机规则沿用（PROTOCOL §8.3）：连续亏损 / 高水位未恢复 / 无 D → `B_e = 0`，挖矿收益为零，不用下一轮借款补上一轮。
- 递减曲线建议：`eraBudgetCap` 每 90 纪元减半一次，直到稳态由真实服务费补充（P4 之后）。系数是版本化参数，不追溯改变已结算纪元。
- 池余额不足时按份额比例结算，**欠发部分自动作废**，禁止记为负债。

### 6.2 个人份额

```text
share_i = w_class(unit) × q_i × u_i        （按座封顶）
q_i = 质量系数：正确率、提交延迟、uptime（W3 心跳连续性）
u_i = 座位利用系数：本纪元有效工作单元 / 配额
结算：reward_i = B_e × share_i / Σ share，且 reward_i ≤ seatCap_e
```

- `seatCap_e`（每座位每纪元奖励上限）与 `voteCapPerRunner` 同源纪律：多开运行器、多开钱包不增加份额。
- 质量系数只能下调不能上调：一次争议败诉下调本纪元系数，不追溯已结算历史。
- 「采蜜量」（verified work units）只是**展示计量**，不是第二货币；结算资产只有 IFS。

## 7. 反作弊与罚没

| 攻击 | 对策 |
| --- | --- |
| 女巫多座 | 座位绑 Soul（一地址一生一孵 Gen0）+ 最少 IFS 占用 + 座位配额与奖励封顶 |
| 多开运行器刷分 | 同一矿位 `seatCap_e` 封顶；运行器 ≠ 矿位（§21.3 对象模型） |
| 自选任务刷分 | 任务经 era 头哈希确定性指派，不可自选；抽签可复算 |
| 提交假结果 | 复核抽签 + 复算包可重放；错误结果 dispute → 罚没 IFS 占用进蜂巢 |
| 复核共谋 | 复现者封顶 + 独立性判据（不同运营控制方才计独立复现；§21.6） |
| 领单不干活 | 配额浪费 → `q_i` 下调；连续空跑 → 座位 HOLD（复用 hosting HOLD 语义） |
| 用未来的钱 | 不存在：预算桶现结，无借贷、无负债、无「质押挖矿收益承诺」 |

罚没去向只有蜂巢，单独记账「罚没」，禁止写成销毁（销毁证据定义见 §8.2）。

## 10. 诚实边界与未决问题

**诚实条款：**

1. 本机制是**验证经济的激励层**，不是 PoW，不是 DeFi 收益产品，不承诺任何收益率或回本周期。
2. 「挖矿」产出的是可复算的计算证据；在 T3/T4 对照通过前，禁止表述为「群体智能已实现 / 因挖矿变得更聪明」。
3. 矿机 ≠ 神经元所有权；官方连接组普查不可被矿工写入（L0 层只随数据集版本升级）。
4. 奖励池余额、纪元预算、递减系数、封顶与罚没记录全部公开可查；数字标注 audit 层。
5. 官方启动期一切成果最高标「经内部验证」；只有不同运营控制方的复现出现后才可用「独立复现验证」（§21.10）。
