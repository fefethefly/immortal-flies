## 0. 核心决定

**一种工作、两条轨、四本账。**

- 工作 = 把一条生命（全量 MaleCNS 状态）从检查点 a 确定性推进到检查点 b，并对整条轨迹作 Merkle 承诺。这叫一「段」。
- 节点跑段（Runner）、保管证据（Keeper）、抽检别人的段（Checker）。IFS 是培养基、押金、工价、座位锁，四本分账。Soul NFT 是**被跑的那条生命本身**——工作的主体，不只是工作的签名人。
- 轨迹承诺与抽样复核：承诺之后才知道抽哪几个叶；开叶必须带前一个检查点；复算者重放 ≤ 2c 步。末叶无条件绑定 `finalRoot`。争议二分到单个叶，任何人 `step()` 一次判负。这是机械谓词，不是链上终局证明；双方不合作时由超时双输或指定仲裁结束。
- 需求侧从第一天存在：主人或围观者给自己那只 `lifeId` 的培养基添 IFS。公共轨（蜂巢税切片实到账）之后再开。

## 3. 段原语

```text
段 = (lifeId | taskId, startRoot, inputRoot, steps n ≤ 1000, checkpointEvery c, leafEvery L, runtime/dataset/端序版本)
```

- 位置 p ∈ {L, 2L, …, n}。每到一个位置取一个**叶** = `hash({schema:"iff.trajectory-leaf/1", position, stateRoot})`，`stateRoot` = 状态的 canonical SHA-256，与 `LifeJournal` 的 `stateRoot` 同义（LIFE-PROTOCOL §5）。位置进哈希，叶不能在槽位间平移复用。
- 每 c 步落一个**检查点**（完整状态），位置 0, c, 2c, … < n。
- **承诺** `iff.segment-commitment/1` = `{steps, checkpointEvery, leafEvery, startRoot, finalRoot, root, checkpointRoots[]}`。`root` 是全部叶的 Merkle 根（`iff.merkle/1`，奇数节点原样上提）。私有轨里它就是 `LifeJournal.checkpoint(...)` 的 `archiveHash` 原像的一部分。
- L 是承诺形状的一部分：同一段 L=1 与 L=10 的 `finalRoot` 相同、`root` 不同。L 必须整除 n 与 c。

### 3.1 证明：承诺 → 抽种 → 开叶 → 复算

1. **抽种**在承诺之后：`hash({seed, segmentId, stratum})`，seed 取承诺交易之后 ≥ 2 个区块的哈希（SIM 显式注入）。种子只决定抽哪里，不决定钱。
2. **分层抽样** k=3：把全部叶切成 3 层，每层抽一个。「只跑前缀」的伪造者不管种子怎么偏，整层伪造必被抓。
3. **开叶**：Runner 公布叶、Merkle 路径、锚检查点 q₁ = ⌊(p−1)/c⌋·c 的**前一个**检查点 q₀ 的完整状态。
4. **复算**：Checker 核 `hash(q₀ 状态) == checkpointRoots[q₀]`，从 q₀ 重放到 q₁ 核衔接（防「循环轨迹」伪造：检查点各自自洽但互不相连），再从 q₁ 重放到 p 核叶，最后核 Merkle 路径（用承诺里的叶数重建层形状，伸缩证明必拒）。总重放 ≤ 2c 步。
5. 任何一步不匹配只标 `CHALLENGED`，不罚。罚只发生在 §4。

为什么抄不比跑便宜：**这个 620 MB 算法不成立，已撤回。** 叶是 `hash(position, stateRoot)`，不含完整状态。1000 个叶哈希约 32 KB；L=10 的 100 个叶约 3.2 KB。协作方仍可共享检查点或按需转发开口。至少一个人跑过，只能说明有人做工，不能说明每个收费副本都独立做过。私有轨要管的是正确交付与不重复支付；公共独立复现另行管理关联方。残余风险仍是同一运营方多座位共享轨迹，用运营方登记 + 副本排他（Hive §4.1）处理。

## 4. 争议谓词

两方对同一段承诺了不同的根：

1. **二分**：两棵同形状 Merkle 树逐层向下比对 32 字节，log₂(叶数) 轮定位首个分歧叶（父异子同则树不自洽，直接判不自洽方输）。
2. **判定**：双方公布分歧叶前一个叶位置的状态（应相同，否则再二分）；任何人 `step(preState, graph, L)` 一次，算出应有的叶。与之相等者胜；都不等则双输。
3. **入账**：输方押金按本段曝险（`bondMultiple × fee`）罚没进蜂巢 `0xfAdb2FE136c89866Cd1CB0DD31298e08cc61a467`，单列「罚没」；无理挑战者罚 `challengeBond`。已付工价只追回尚未提取的部分；未付预留费按原路退回买方。

这是 Hive 稿 §6 要的「可验证违规谓词」。只有它能开罚没；哈希不匹配、版本不符、序列化差异一律不能。

不变量（`invariants()` 每次操作后都成立，单测逐步断言）：

- 守恒：`totalIn === Σ培养基 + Σ押金 + Σ座位 + 预算资产 + Σ未提工价 + totalOut`。
- `budget.assets ≥ budget.liabilities ≥ 0`。
- `SLASHED` 只能来自 `verdict ≠ "A"` 的判定记录。

工价与押金：私有轨 `fee = 绑定时接受的报价 ≤ maxFeePerSegment`，是服务费，进 PRODUCT-LATEST §8.2 的 R 口径，量级是「养一天几分钱 IFS」。公共轨 `fee = 预登记价`，副本排他（同一运营方不能跑同一任务两个副本）。争议后剩余一致副本 ≥ `minAgreeingReplicas`（建议 2）才付，否则退预算——这是未决参数，见 §11。押金目标是让伪造期望值为负：`bond ≥ fee × 挑战窗内并行段数 / p`；实现里取 `bondMultiple = 5`，即最多并行 `bond / (5 × fee)` 段。

| `structuredClone(state)`                | 23.8 ms                                                      | `voltage` / `refractory` 是 161,839 长的普通 Array；`step()` 每次调用克隆一次 |
| `hash(state)`（canonical JSON 0.62 MB） | 15.8 ms                                                      | 叶与检查点摘要的成本                                                          |
| L=1 逐 tick 取叶                        | 41.7 s / 段（41.7 ms/tick）                                  | 设计稿原案。**40× 内核成本**，瓶颈是每 tick 的克隆 + JSON 哈希，不是神经计算  |
| L=10                                    | 4.9 s / 段（100 叶）                                         | 4.6× 内核成本                                                                 |
| L=50                                    | 1.9 s / 段（20 叶）                                          | 1.8× 内核成本                                                                 |
| 抽检 k=3 复算                           | 重放 368–550 步，640–816 ms 总计                             | 浏览器可做；开口 0.62 MB × 3                                                  |
| 检查点                                  | 10 × 0.62 MB                                                 | 证据包主体                                                                    |
| 二分                                    | 10 / 7 / 5 轮（L=1/10/50），< 1 ms                           | 每轮 32 字节                                                                  |
| 判定                                    | 100–140 ms（含从检查点重放到前一叶 + 哈希）                  | 任何人可做                                                                    |
| 蒙特卡洛（400 次 × k=3 分层）           | 只跑 50%：被抓 100%；只跑 90%：约 30%；诚实：0 误报          | 押金倍数依据                                                                  |
| 逐位一致门                              | 逐 tick 终态 == 批量终态；两次独立跑同根（L=1/10/50 均通过） | 同机通过；**跨平台未测**                                                      |

结论与后续（不在 M0 内）：

1. 逐 tick 叶（L=1）在当前内核接口下不经济。三个修法，任选其一即可回到 L=1：`step()` 加逐步观察回调；`voltage` / `refractory` 改 typed array（这是 `iff.state/2`，牵动全部快照）；叶摘要改二进制 `iff.trajectory-leaf/2`（检查点仍用 canonical，才能对上 LifeJournal 的 `stateRoot`）。M1 前不动内核，默认 **L=10**：争议判定重放 10 步（约 11 ms），谓词仍是机械的。
2. 抽检成本约为段成本的 1/7（L=10 时 0.7 s / 4.9 s），未达到设计稿估的 1/10；把 c 从 100 降到 50 即可，代价是检查点翻倍。
3. 跨平台（macOS / Linux / 浏览器）1000 步逐位一致与 graph.bin 端序钉死是 M1 的门，未过之前不开真钱。Darwin/arm64 向量已写入 `reports/segment-replay-full-v1.json`（circuit + full，L=10）。Linux 门：`.github/workflows/segment-replay.yml` 跑 `node scripts/segment-replay.mjs verify`。浏览器门仍未做。向量构建时拒绝非小端 IFF1 的 `graph.bin`；未改 `graph.mjs` / `graph-fs.mjs`，以免打现有研究包源码指纹。
