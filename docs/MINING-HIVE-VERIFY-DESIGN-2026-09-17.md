## 0. 核心决定

**节点提供可核验的服务，IFS 提供履约保证与任务结算，Soul NFT 承载参与身份与贡献历史。只持币、只持 NFT、只挂机，不自动产生收益。**

「矿」是蜂巢实际需要且验收通过的工作，不是无限重复同一份计算。PoUW 在这里是应用层任务激励的名称，**不是新链共识、出块机制或已实现的密码学计算证明**。

沿用原稿的卫星架构、零增发和 W1/W2/W3 分类，重点补齐：

1. 任务必须先有需求、预算与验收条件；验证容量不足就不开对应付费任务。
2. 官方不能复现自己的结果领取社区奖励；独立性按实际控制关系审查，不按钱包计数。
3. 奖励拆成验收后可领取部分与延迟释放部分，全部提前预留资金。
4. 争议先复算、再裁决；哈希不匹配不是可自动罚本金的充分证据。
5. NFT 历史永久留痕，当前运营资格不随交易自动继承；不发行第二种矿币。

## 2. 三件套与参与角色

### 2.1 神经元网络节点：工作台，不是神经元产权

区分四个对象：图里的神经元、运行生命的 LifeInstance、执行程序的 Runner、提供计算/存储的 ComputeNode。数量不能互相替代。

- `malecns-circuit`：浏览器学习、子图重放和兼容性练习。首版不分配真实 IFS；贡献凭证标 SIM。此为试点范围选择，不代表浏览器永远不能提供付费服务。未来经批量结算与成本验证后另评估。
- `malecns-full`：合格社区运行器执行登记任务。不能凭「全量图」标签获得固定倍数；不同模型的 tick 不作为等价算力单位。
- 官方运行器：产出基线、日志、任务与运行保障。自有成本从公开运营预算支付，不从社区奖励池领取自证奖励。
- 存储节点：可以不运行神经内核，但必须证明约定数据在服务期内可读取、可恢复，不能冒充神经计算节点。

首版以完整任务重放为主，不假设把单个脑拆到多台机器就会更快；分片动力学的同步成本与正确性需独立设计。

2026-09-17 源码核验：`src/brain/flyswarm/mesh.mjs` 的分片目前只有区域、计数与状态等声明字段（declared hosting），没有神经元索引分区、跨分片脉冲传输或任何 P2P 传输层。因此 W3 的「挑战-应答」验证语义在真实分片执行设计出现前保持未定义：W3 不进付费任务目录、不配预算（§10 M3 门不变）；「mesh 覆盖率」不得对外表述为算力或存储证明。

### 2.2 IFS：履约押金与任务报酬

- 付费座位需占用专用履约押金；押金与奖励池隔离，不挪押金发奖励。
- IFS 是唯一奖励结算资产。观察、兼容性检查和 SIM 练习不强制质押。
- 质押量只约束风险敞口与可承接任务，不线性放大奖励、投票权或智能评分。
- 押金按任务风险与争议期限设定，不能直接照搬 SIM 的 `bondedStakeMin: 10_000` 为主网金额。主网必须核验代币 decimals、转账行为、可用流动性和精确计量。
- BNB 用于 gas 或明确计价的服务轨道，不修改生命身份；税入账、质押、罚没均不是销毁。

### 2.3 NFT：身份、历史与可选执照

| 对象         | 本设计语义                                             | 阶段与限制                                                    |
| ------------ | ------------------------------------------------------ | ------------------------------------------------------------- |
| Soul NFT     | 参与主体；用生命协议的 canonical `lifeId` 关联工作历史 | 复用现有集合，不改 Soul，不要求再买一枚矿机 NFT               |
| History NFT  | 可选复算纪念章，关联回执、证据包及渲染版本             | M1 可做测试网样品；主网发行另审。不是收益权，也不代表实验增益 |
| Position NFT | 可选工位授权凭证，不是永久产能或保底收益合同           | M3 再议；v1 用卫星座位记录即可，不允许与金库 Position 混淆    |

历史记录挂 `lifeId` 永久保留；有效运营信誉绑定 `(lifeId, operatorId, reputationEpoch)`。Soul 转移、运营控制方变化时开新信誉期，旧记录不删除，新主人不继承奖励加成或验证权限。

`authorizedRunner` / `controlEpoch` 用于当前会话授权，换 runner 不应抹掉同一运营方的历史。矿工签名、委托分账、任务领取人和奖励受益人在领单时固定，不能仅凭 Soul 的 runner 授权提款。

NFT 转移不转走旧任务的押金、已分配报酬或责任；旧任务按原参与者继续结算，新控制者不得借转移重复领单。卫星独立递增自己的授权 epoch，不能假设它能写 Soul 的 `controlEpoch`。

## 3. 工作目录与验收

所有付费任务先登记需求方、预算、模型与输入版本、服务范围、重复副本数、截止时间、验收和争议规则。同一工作只能在明确批准的副本配额内付费。

| 类别        | 有用产出                                              | 计酬与验证边界                                               |
| ----------- | ----------------------------------------------------- | ------------------------------------------------------------ |
| W1 复现     | 从固定初态与完整输入恢复指定任务/日志结果，提交复算包 | 验证计算与结果，不是复制公开头哈希；同控制方互验不算独立复现 |
| W2 隔离评测 | 冻结候选与基线在预登记任务上的完整评测报告            | 正确执行即有服务价值；负结果照样计酬，不能只有候选达标才付钱 |
| W3 托管     | 约定时间段的数据保存、可读取、恢复或运行服务          | 按服务时长与挑战验收；心跳不是存储证明，存储应答不是计算证明 |

### 3.1 不能靠公开哈希证明矿工做过计算

哈希提供完整性承诺，不证明某人亲自执行、算力独立或数据一直可用。给公开结果补一个 nonce/签名仍不能解决这一点。

首版采用已登记执行者、任务级独立复核、提交截止前的结果承诺、封存的诊断输入及有预算的抽检。它们提高可核验性，**不构成通用防抄答案证明**。能低成本外包、转发挑战或共用上游资源的风险须披露；无法达到验证要求的任务不开放无许可真钱领取。

验证工作本身必须有配额和报酬，禁止「复核复核者」无限递归产生奖励。官方生成结果和社区验证结果均可被质疑，不把官方输出当作不可推翻真值。

### 3.2 评测正确不等于候选成功

先冻结候选、基线、评价指标和预算，再由隔离评测方保管或生成留出条件。测试完成后发布必要种子、输入和结果供重放。普通开放 worker 看见测试集后就不能继续宣称它是秘密留出集；首版披露隔离评测方信任边界。

「候选未达到晋升阈值」不罚执行者、不扣正确评测报酬。候选提出奖励如未来开放，单独登记，不能与 W2 基础报酬混用。

### 3.3 防重复补贴

同一服务按 `(taskHash, scope, serviceWindow, replicaIndex)` 去重。已拿 hosting 服务费的相同交付，默认不再领取 W3 奖励；政策若补贴增量副本，须单列新增交付、总价与资金来源。

不得用两笔不同质押掩盖对同一服务的重复支付；也不得把同一笔押金重复支撑 hosting、mining 或借贷风险。

## 4. 独立性与任务分配

### 4.1 首版承认准入与仲裁的中心化边界

一地址一生一孵只限制 Gen0 铸造；多钱包、购买 Soul 和后代持有均不能证明独立。质押、冷启动和座位封顶只能增加成本，不能解决女巫。

首版真实付费验证采用公开规则下的运营方登记：声明共同控制、关联机构及共享基础设施，保留审核、异议和撤销记录。`operatorId` 是登记索引，**不是链上可自动证明的真实身份**。不同 IP、地区、公钥也不是独立性的充分证据。不公开敏感身份材料，只公开必要结论、依据类型和利益冲突。

- 同一已知运营控制方合并计算奖励上限和复核资格；未识别的隐藏关联是残余风险。
- 任务提交者、结果生产者、出资且参与裁决者及其关联方回避该任务的独立复核。
- 官方实例不领取自己的 W1 奖励，也不作为社区独立复核人；独立方不足时该任务不开放付费，不降低标准凑人数。
- 建议试验值为每任务 K=3 个独立复核方；K 不是安全证明，上线值须结合成本和共谋风险验证。
- 非独立的官方重复实验仍可运行并标「内部验证」，从另列运营预算支付，不冒充社区矿工收入。

### 4.2 结算钟与日志分片分开

```text
settlementEpoch = floor((settlementTime - epochOrigin) / epochDuration)
epochDuration   = 24 小时（建议值）
logRefs         = 本纪元任务引用的已封口日志根与 tick 范围列表
```

SIM 注入显式测试时间；链上结算使用规范约定的链时间及确认规则。不用浏览器时间决定领取资格，也不从日志高度推算墙钟。一个结算纪元可引用多个日志分片，空纪元可以跳过；跳过不停止既有奖励的释放计时。

### 4.3 可复算分配不等于公平随机

先冻结符合资格的运营方名单、任务目录、预算和版本，再取得本轮分配种子；记录冻结与种子来源的顺序证据。随后按固定算法分配并排除关联方，同一方不能通过重新申请反复抽签。

**不采用「官方先 commit 再 reveal 就能保证公平」的说法。** 单方可事先试选种子或拒绝揭示；可控的 era 头也可引入偏差。多方 commit–reveal 仍有最后揭示者中止风险。

M0/M1 使用明确标注的测试种子验证分配逻辑；真实试点必须选定可审查的随机来源、不可见种子前的名单冻结、超时处理和抗重抽规则。VRF 等外部来源只是待评估选项，本稿不声称已集成。随机来源失败则取消未开工任务并释放预算，不由官方挑替代种子。即使种子公平，也不能消除隐藏关联或评测数据泄漏。

## 5. 预算与报酬：先预留，后领单

### 5.1 资金来源与守恒

沿用 D 的生态任务拨定边界，不增发、不借未来、不用用户本金或押金垫付。D 的账面数额不能直接当 IFS 数量；只有经过批准拨定、必要兑换并实际到账的净 IFS 才可发单。记录拨定来源、兑换成交、费用和入账回执，不把矿工结算兑换称为销毁。

```text
A = 奖励池实际 IFS 余额（不含押金）
L = 已预留任务、争议冻结、待领取及延迟释放金额的总和
F = max(A - L, 0)
B_e = min(F, 本纪元预算上限)
```

`L` 各项互斥记账，状态转换不能重复计入；常态必须满足 `A >= L`。不足意味着异常，停止新单并披露，不能把已分配报酬自动作废来做平账。

预算须覆盖执行、复核、争议处理和证据保留费用。低于最小可运行任务包预算，或缺乏独立复核方，则不开该包。最低预算来自成本测量与参与报价，不来自假定币价或目标收益率。主网金额为整数原子单位，链下使用安全的精确整数表示。

**首个物理资金来源（M2 试点命名）**：蜂巢钱包 `0xfAdb2FE136c89866Cd1CB0DD31298e08cc61a467` 当周税入的固定小比例（建议 ≤5%，先观察 30 个结算纪元），经拨定、必要兑换并实际到账后才计入 `A`，拨定与兑换回执公开。税入划拨单独记账：税进钱包 ≠ 回购 ≠ 销毁，也不表述为「金库在交易」。外部需求方登记的任务预算另行直接计入 `A`，与税入分列披露；无外部需求且税入为零时，奖励池为零、不开新单，属正常状态而非故障。

### 5.2 任务定价优先，份额奖励后议

v1 使用**预登记任务报酬和配额**，不强制花完纪元预算：

```text
reward_i = Σ 已验收任务为参与者 i 预登记的报酬
Σ 全部任务最大承诺报酬及验证费用 <= B_e
```

领单前检查每座位和每运营方上限；不得验收后才用新封顶削减已约定报酬。预留完成后才能派发任务；未领取或按条款取消的任务预算才能释放。

原讨论的 4:4:2 权重、稀缺加权、按活跃座位数动态封顶、质押年龄加成和 90 纪元减半不进入 v1。它们未经验证，且身份拆分可能操纵分母。需求稀缺时，只能在下一轮预先公布新价格，不追溯修改已领任务。

停机或无 D 时不新开补贴任务，但必须继续处理已预留任务、争议和领取。没有持续收入就不能承诺持续社区验证；必要的官方维护与免费复现须另列成本和责任，不能靠「以后币价上涨」补缺口。

### 5.3 验收后领取 + 延迟释放

建议在测试网试验 70% / 30% 结构，非最终参数：

1. 接单时预留任务全部最大报酬。
2. 提交后进入初始复核和挑战窗，尚无可领取奖励。
3. 初始验收通过且无待决争议，70% 进入可领取余额；30% 进入已足额预留的延迟奖励。
4. 延迟部分在随后 4 个结算纪元按预定规则释放；整数余数在最后一期结清。新发单停机不暂停这只时钟。
5. 有效争议只冻结相关任务尚未释放金额。裁决推翻时，按预先条款取消该任务可取消的未释放部分；已经领取部分不自动追回，并披露协议残余损失风险。
6. 单笔可领取金额低于公示阈值（按当期 gas 参考成本与 IFS 计价，版本化更新）时不单独发放，自动滚存至下一结算纪元合并结算。滚存不改变第 4 条的释放时钟；座位退出结算时一次性付清剩余滚存。

这是**有足额资金覆盖的结算义务**，不能称为「完全没有负债」。延迟释放不证明诚实，只降低部分事后风险；长期伪造的收益仍需与检测概率、复核成本及押金风险共同评估。

## 6. 争议、罚没与退出

**哈希不匹配仅触发复算排查，不自动证明作弊。** 先排除模型/输入版本不一致、序列化差异、运行器缺陷、官方参考结果错误和证据缺失。

| 情况                       | v1 处理                                                          |
| -------------------------- | ---------------------------------------------------------------- |
| 候选表现差，但评测执行正确 | 正常付 W2 报酬，候选不晋升                                       |
| 无法交付或结果不合格       | 按预登记验收条款拒付相关服务；系统性缺陷单独处理，不默认归责矿工 |
| 有证据支持的结果争议       | 冻结相关未释放报酬，复算、答辩、裁决并记录依据                   |
| 只有猜测，没有可验证证据   | 不扣本金、不取消已验收奖励；必要时有限期暂停新领单并允许申诉     |
| 可归责且预定义的严重违规   | 未来才考虑本金罚没；必须另行安全审计与规则批准                   |

建议流程：证据挑战 → 通知双方 → 72 小时答辩窗 → 回避关联方的复算 → 公示裁决 → 独立于初审的申诉 → 最终执行。答辩窗、裁决和申诉最长期限须在 M1 前确定。超时不得无限 HOLD；不同超时原因对应的释放/取消规则需预先固定，无可运行仲裁流程则不开放真钱任务。

首版官方仲裁属于受信任治理，不包装为链上自动证明。必须指定发布权限、程序审查、利益冲突回避与可审计证据；仅凭多数钱包投票不能安全地决定本金归属。

**M2 小额试点默认关闭本金罚没。** 上轮讨论的「哈希不匹配罚至多 20%」撤回为未采纳参数：没有经过验证的客观违规谓词与申诉程序，比例再低也不应启用。未来罚没只能针对事先明确、可归责且可验证的违规，限额不能追溯提高。罚没转入经核验的蜂巢地址，单列「罚没」，不是销毁；不作为常规奖励资金来源。

退出先停止领单，完成在途任务及有限期争议，再解锁押金。NFT 出售或 runner 撤权不免除旧责任；争议冻结金额、期限和退出路径公开，不允许管理员无限锁资。

## 7. 证据包与存储责任

任务必须携带可恢复的证据包：dataset/runtime/adapter/evaluator 的版本和工件哈希、基线与候选、初始状态、完整输入与通信日志、预算、输出、任务分配、签名和复核记录。只存 URI 或根哈希不算可恢复。

- 派单时指定责任人、镜像位置、保留到期时间、恢复目标和资金来源。
- 热存储至少覆盖全部复核、答辩、申诉及延迟释放窗口，不能简单保留两纪元就删除。
- 温归档可试验最终结算后额外保留 30 天，数值待容量实测；到期前允许公开导出并提前告知。
- 被晋升经验或 History NFT 引用的证据需有长期归档方案、冗余镜像和定期恢复检查。没有持续资金与可执行责任，不承诺「永久镜像」。
- 数据缺失单独标记 `EVIDENCE_UNAVAILABLE`；历史链上记录仍存在，但不能继续展示「当前可重放」。W3 的抽样挑战提高可用性信心，不证明持续保存独立物理副本。

## 8. 最小对象与卫星接口

以下是候选字段，不是已冻结 schema；M0 从实际用例收敛，不先写完整协议家族。

| 对象        | 建议 schema / 必要内容                                                        |
| ----------- | ----------------------------------------------------------------------------- |
| MiningSeat  | `iff.seat/1`：lifeId、operatorId、reputationEpoch、授权会话、押金引用、状态   |
| WorkUnit    | `iff.work/1`：内容寻址任务、epoch、分配版本、范围/副本、报酬、验收与存储条款  |
| WorkReceipt | `iff.work-receipt/1`：任务/参与者/签名、输出与证据、复核方、裁决和结算引用    |
| MiningEra   | `iff.mining-era/1`：墙钟边界、logRefs、政策版本、名单承诺、随机来源与预算预留 |

未铸 Soul 的官方实例用 `instanceId`，`lifeId` 为空；仅参加内部/SIM 轨道，不伪造链上身份开社区付费座位。签名域绑定链、卫星合约、任务、纪元、参与者、授权 epoch 与 nonce，防跨链/跨合约/重复领取。

建议独立 `MiningHub` 卫星：登记座位与押金 → 预留并派单 → 提交承诺 → 复核/争议 → 领取/释放 → 退出。不写 Soul，不调用 `mintDescendant`，不进 `modules[]`。链上保存必要授权、预算、承诺与结算；神经状态和完整证据链下保存。主网重放裁决如何认证，必须在合约设计时说明，不假装合约会执行全量神经计算。

批量提交/领取可作为成本优化，但须有逐任务去重、可重算分配、挑战窗与唯一领取标记。管理员提交的 Merkle 根本身不是正确结算证明。

回执分列：链环境 `SIM/TESTNET/MAINNET`、执行验证状态、任务增益结论、独立性状态。主网上链不提升科学证据等级。

## 9. NFT 体验与信誉边界

用户流程：持有 Soul → 免费检查运行兼容性 → 登记运营方与委托 → 查看有预算的任务 → 占用押金并执行 → 查看独立复核 → 领取报酬 → 可选保存复算纪念章。

History NFT 的画面可以来自真实重放轨迹，必须同时关联生成算法版本、输入哈希和原始回执；画面是可追溯表达，不是脑状态本身。区分「执行复现纪念」与「实验增益纪念」，后者必须有对应 T3/T4 证据。不得写收益权、稀有级、地板价或自动信誉加成。

主网纪念章存在 gas、持久存储、欺诈和合约风险，不能称零风险。M1 只测试可选领取；是否可转让、谁付费及过期证据怎样提示，主网发行前另定。纪念章持有人不自动等于原贡献者。

Position NFT 如上线，转移只改变未来授权资格；旧报酬、押金和任务分别结清。新控制者需重新通过准入，冷启动期可试验 4 纪元但不作为反女巫证明。买工位不买旧信誉、不自动获得别人的脑会话或数据控制权。

## 10. 分期与验收门

| 阶段              | 交付                                                           | 必须通过的门                                                          |
| ----------------- | -------------------------------------------------------------- | --------------------------------------------------------------------- |
| M0 本地 SIM       | 最小座位/任务/回执账本，预留、验收、争议、延迟释放与退出状态机 | 确定性重放及下列账本不变量测试；不部署、不真钱                        |
| M1 测试网         | MiningHub 最小路径；可选 History NFT 样品                      | 授权、转移、重复领取、超时和恢复端到端；明确随机与仲裁方案            |
| M2 主网小额试点   | 已登记独立运营方、足额预留任务、延迟奖励；默认不罚本金         | 资金轨道/合约审计、实际服务报价、完整争议机制、恢复演练与显式部署批准 |
| M3 社区扩展       | W3 真实服务与容量验证；Position NFT 再议                       | 防重复补贴、独立性审查、数据恢复与新控制者准入                        |
| M4 治理与长期归档 | 仲裁多方化、长期证据责任、开放准入评估                         | 共谋成本与经济压力测试；不能只按节点数宣布去中心化                    |

W2 在任务与隔离评测验收后才进入付费目录；W3 在服务和恢复验证后才开放。挖矿不阻塞 Soul 孵化、转移或原有实验；不能因加入奖励就跳过 T0–T4 证据门。

### M0 必测与试点指标

- **资金守恒**：余额覆盖所有预留；预留/冻结/领取/释放无重复记账；预算为零不新开单；停机不吞掉存量义务。
- **重复与授权**：重复回执和领取被拒；同一抵押不得双占；相同服务跨 hosting/mining 不双付；Soul 转移不夺走旧报酬、不复用旧授权。
- **争议边界**：哈希不一致不自动罚本金；正确负结果获付；只冻结相关任务；答辩、申诉与到期可重放。
- **随机与独立性**：名单必须先冻；关联方回避；不足 K 不开对应单；来源超时不重抽择优。
- **计时与整数**：页面暂停不影响结算钟；跨日志分片无歧义；取整尾差守恒；延迟奖励在停止新单后仍释放。
- **故障恢复**：断电重启、重复事件、证据缺失、版本不一致和结算重组处理；同输入重放得同账本。

试点报告公布每份有效交付的执行/复核/存储/gas 成本、独立覆盖率、结果争议率、证据恢复成功率、结算延迟、已知控制方集中度和预算消耗。性能与经济阈值由 M0/M1 实测后预登记，不在本稿虚构通过数据。
