# 三层运行架构：全量连接组运行器与 dataset 注册表设计

日期：2026-09-17。状态：**设计稿，未实现**。本文回答「官方跑全量 16 万节点是否可行」的结论（可行；成本量级为估算，见 §2），并给出实现路径。产品正文已收录群体智慧协议裁定，见 [PRODUCT-LATEST.md](PRODUCT-LATEST.md) §21；本文只负责运行分层与 dataset 注册表。D4 单实例 Railway 对应群体智慧 S6，排在本机 T0–T4 对照之后。上游依据：[CONNECTOME-MALE-CNS.md](CONNECTOME-MALE-CNS.md)、[BRAINWEB-RESEARCH-2026-09-17.md](BRAINWEB-RESEARCH-2026-09-17.md)、[SWARM-INTELLIGENCE-PROTOCOL-DESIGN-2026-09-17.md](SWARM-INTELLIGENCE-PROTOCOL-DESIGN-2026-09-17.md)。

## 0. 一句话

浏览器子图是橱窗，官方全量运行器是后厨，社区 mesh 是外摆。三层共用同一份官方连接组谱系，靠 dataset 注册表和投票权规则衔接。

## 2. 本地可运行性实测与容量边界

> **来源待确认**：本节包含两组数据。「已核验」组是本设计会话于 2026-09-17 在独立 Node 进程实测（seed=43，food=800，`loadGraphFromDir` 全量图 + `step(state, graph, 32)`）：加载 167 ms、加载后采样 RSS 231 MiB、摊销 4.84 ms/步、末步 3,477 脉冲、同进程逐位重放一致。其余更详细的数字（机型/Node 版本/p50/批量步进/RSS 峰值/状态体积）**来源未经证实，使用前须由你方复测**，在 D3 基准确认前不作为扩容或计费依据。

2026-09-17 本机实测；具体机型与 Node 版本未记录。方法：复用现有内核 `prepareGraph` + `createState` + `step`（`src/brain/graph.mjs`、`runtime.mjs`），**零代码改动**；manifest 的 metadata/connectivity sha256 校验通过。这不是 Railway 测试，也不是完整服务压测。

| 测量项 | 结果 | 能证明什么 |
| --- | --- | --- |
| 图加载（读盘 + 解析 + prepare + 哈希校验） | ~156 ms | 本机单次读取；未控制操作系统文件缓存 |
| 常驻内存 | 空闲 ~215 MiB RSS；活跃 ~310 MiB；本进程峰值 ~371 MiB（含两轮负载与断言） | 1GB 内存档云实例可行；非云端实测 |
| 单步耗时（逐步调用，max-sensory 刺激） | p50 ≈ 25 ms，p95 ≈ 27 ms，max ≈ 48 ms（均值 ~3,100 脉冲/拍） | 活跃全量脑单步成本；逐步调用含每次 `clone(state)` 开销 |
| 批量 `step(state, graph, 128)` | 摊销 ~2.5 ms/步（mixed / max-sensory 两刺激一致） | 运行器实际形态（批量推进）的成本 |
| 每 Fly 状态体积 | JSON ≈ 0.95 MB（16 万电压 + 16 万不应期） | 链下快照/检查点量级；二进制化可再压缩 |
| 重放一致性 | 逐步 256 步与批量 128+128 步终态**逐位一致**；JSON 往返恢复一致 | 本进程确定性；跨机器一致性待 CI 化长期保障 |

输入：seed=43；mixed = {food 800, threat 120, light 200}，max-sensory = {food/threat/light 全 1000}。内核是整数化离散 LIF（JS Number 与 Float64Array），每拍只遍历上一拍发放神经元的出边（CSR 固定顺序），并非每步扫全部 275 万边。该短测不含网络、日志持久化、链上提交或并发服务。

**已证明：现有内核零改动即可加载并推进 161,839 节点全量图，活跃脑每秒一步的算力余量极大。** 尚不能承诺云端长期运行的容量与价格；撤回此前未经核验的 $5–10/月实例报价与 CPU 占用比例。费用按 Railway 当期 CPU/内存/存储/流量/套餐规则及目标负载计算，D4 在目标实例复测同四项（加载 / p50 / 批量步进 / RSS 峰值；云实例预期慢于本机，按最差数倍留余量）。

同进程内可让多个状态引用一个只读 graph；多个进程或 Railway 副本**不会自动共享图内存**。每个生命还需独立状态（~1 MB JSON 量级）、临时缓冲、日志与检查点，CPU 成本随实例数和活动水平增加。扩容前补并发数量、长时间恢复及云端复测。

### 2.1 Railway 平台可行性（部署约束，需在 D4 逐条核实）

- **图不入库是部署堵点**：`malecns-full/` 不在 Git 里（仓库约定），运行器不能假设镜像内有图。两个选项：(a) 构建期从 Janelia 源下载 + 校验 manifest 三个 sha256 后烘焙进镜像；(b) 启动时下载并校验 manifest sha256，缓存到卷。**选 (b)**，同时满足许可（CC BY 署名须保留在 API/页面 footer）与内容寻址纪律。
- 部署形态：仓库根 Dockerfile（Node 22），Railway 按 GitHub 推送自动构建；1GB 内存档起步，healthcheck 挂 `/health`（API-V1 已有该端点模式）。
- 待核实项（本节不预设结论）：当前账号套餐的实例规格上限、计费口径、持久卷是否需要（快照存储可以先用对象存储/本机盘代替）。
- 厂商锁定对冲：运行器只依赖 Node + HTTP + 文件系统，随时可迁 Fly.io/裸 VPS；协议层不出现任何 Railway 概念。

## 3. 三层架构

```
┌ 浏览器层（现状保留）────────────────────────┐
│ malecns-circuit 1,400 节点实时交互            │
│ 低延迟、零成本、人人可玩；复杂行为上限受子图   │
│ 约束（待验证假设，D5 对照实验确认）            │
└──────────────┬───────────────────────────┘
               │ dataset 谱系：circuit ⊂ full（同一 male-cns:v1.0）
┌ 官方运行器层（新增）────────────────────────┐
│ 3–10 个全量 161,839 节点实例（Railway/Fly.io）│
│ 产出：era 分片日志头哈希、quorum 话语、检查点   │
│ 子集可作 mesh 种子节点                        │
└──────────────┬───────────────────────────┘
               │ iff.mesh-node/1 + iff.hosting-order/1（已有 schema）
┌ 社区 mesh 层（扩展）────────────────────────┐
│ 社区运行器托管子图或全量；IFS 占用质押，       │
│ BNB 只作轨道；不改官方连接组普查               │
└───────────────────────────────────────────┘
```

## 4. 工程纪律（真正的难点）

1. **确定性**：全量图下浮点求和必须固定边遍历顺序（按 body ID 排序的 CSR 固定次序），任何并行归约禁止原子浮点累加。`npm test` 需新增「同种子全量 N 步逐位一致」用例（CI 跑 1,000 步短程，夜间跑 64 步全断言）。
2. **模型身份**：全量内核是新 runtime 版本（如 `iff-runtime-full/1`），与 16 节点原型、子图内核互不冒充。genome/genesis 记录的 `runtime` 字段区分；模型迁移留事件。
3. **检查点**：每 tick 全量状态 ≈ 数 MB，不能逐 tick 上链。沿用 era 分片日志：**链上只放头哈希与输入承诺，全量状态存链下 + 定期快照**；中断恢复从检查点继续（内核已支持）。
4. **投票权 ≠ 规模**：一个官方全量运行器与一个社区子图运行器在 quorum 里的话语权重由 membership 规则决定，**不由节点数决定**。防「多开运行器刷票」：每运行器合计封顶已有（`voteCapPerRunner`），全量运行器不豁免。
5. **诚实标注**：全量运行器产出标 `audit: TESTNET` 直到通过重放审计；浏览器子图继续 `SIM`。三层各自明示运行的是哪个 dataset id。

## 5. Dataset 注册表（新增，替换硬编码 `DATASET_CANON`）

现状：`schemas.mjs` 导出 `DATASET_CANON = "male-cns:v1.0"`，genesis/mesh-node/quorum 均按它过滤。问题：无法区分全量/子图/未来物种，也没法给不同 dataset 声明不同权限。

设计：注册表 = 一组版本化的 `iff.dataset/1` 记录（**manifest 已是该格式**），加两列：

```jsonc
{
  "schema": "iff.dataset/1",
  "id": "malecns-full",                    // 已有
  "dataset": "male-cns:v1.0",              // 已有（谱系）
  "subsetOf": null,                        // 新增：circuit 填 "malecns-full"，全量填 null
  "votingClass": "full",                   // 新增：full / subset / observer
  "contentHash": "0x7fe1b3bc…"             // 已有 connectivity.sha256
}
```

- `subsetOf` 形成谱系树：`malecns-circuit → malecns-full → male-cns:v1.0`；未来物种（如 `celegans:302`）是新的谱系根。
- **quorum 规则改读注册表**：`run()` 里 `u.dataset === DATASET_CANON` 的过滤改为「`votingClass` ∈ 规则允许集」。confidence-hold v3（新版本，不暗改 v2）可声明「full 与其登记子集同票权」或「full 加权」，由政策参数决定，写进规则标题。
- 代码侧最小改动：`DATASET_CANON` 常量 → `createDatasetRegistry(additional)` 实例，沿 `registry.require(id, version)` 既有模式，未知 dataset 大声拒绝。
- **跨物种开关就位**：接受第二条谱系 = 注册表加根，不动 quorum 算法。这是「开放式协议」的第一块真实地基。

## 6. 交付顺序（建议，未排期）

1. **D1** dataset 注册表模块 + 全量/子图 manifest 挂谱系 + 单测（不动 quorum，纯新增）。
2. **D2** quorum v3 读注册表投票类；v1/v2 保留可重放。
3. **D3**（部分完成：基准已在本机跑通，见 §2 实测）全量运行内核 headless 化（复用现有内核接口 + 全量图加载器，内核零改动已验证），固定顺序归约 + 逐位重放测试 CI 化；D4 在目标云实例复测同四项。
4. **D4** 单个官方 Railway 实例跑通：era 日志 + 哈希暴露 `/v1` 端点（复用 `docs/API-V1.md` 模式）。对应 PRODUCT-LATEST §21.11 的 S6；本机 T0–T4 对照未跑通前不把「母体+N 全量脑集群」提前到这一步。
5. **D5** 扩到 3–10 实例 + 接入 mesh 种子；对外发布「验证入口」页（下载 era 日志 → 本地重放 → 比对哈希）。mesh 是算力外摆，不是群体智慧证明。

## 7. 边界与诚实条款

- 全量连接组 ≠ 更聪明：行为增益必须由 D5 之前的对照实验证明（单体 vs 组网，固定预算与种子，见 BRAINWEB-RESEARCH §动作 2）。
- 神经元数量是叙事资产但不是能力证明；对外文案不得声称「完整果蝇脑」「意识上传」。
- 官方运行器是中心化的种子，不是最终形态；协议目标是社区 mesh 可验证接管，官方只留普查与仲裁。

## 8. 竞品策略与对外口径

对照 [BRAINWEB-RESEARCH-2026-09-17.md](BRAINWEB-RESEARCH-2026-09-17.md)：BrainWeb 已用「全量连接组 + 每钱包一个神经元座位」定住市场认知——但**展示全量 ≠ 运行全量**，其脑动力学是否真实运行未经验证。我们的对位：

1. **跟进「官方全量」叙事，用可验证性打差异化**。对外主打三句话，每句都有本文档交付物支撑，说到即做到：官方运行器跑全量 161,839 节点（era 头哈希为证）；群体聚合规则公开且逐位可复算；浏览器子图人人可玩。
2. **不复制「卖座位」**。神经元占用只作参与/赞助标签，不售卖科学意义上的神经元所有权，不自动附带运动控制权（与 BRAINWEB-RESEARCH 动作 3 一致）。稀缺叙事可以有，产权承诺不能有。
3. **不点名贬低竞品**：其实现深度未验证，只陈述我方可复核事实（重放、开源日志、内容寻址）。
4. **验证入口页（D5）是传播资产**：「下载 era 日志 → 本地重放 → 比对哈希」强于 hourly CSV 快照，因为我们的哈希背后是状态机重放，而不只是一张表的快照。
