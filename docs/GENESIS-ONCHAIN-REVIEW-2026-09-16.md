# 创世果蝇上链：代码评审与实施建议

> **历史评审（2026-09-16）。** 对着后来已 RETIRED 的 `/2` 集合与当时的创世草稿。现行集合是 `phenotype-loci/3`。目录：[README.md](README.md)。

日期：2026-09-16。本文是基于 `PRODUCT-LATEST.md` 与当前工作区的评审附件，不替代唯一产品正文。当时不改业务代码、不广播交易。

## 结论

下一阶段应交付：**一份可公开下载、校验与恢复的创世脑；用户可在 BSC 拥有源自该创世记录的 Soul；真实参与事件与连续检查点可在链上查询。**

仅完成 §19 的 NFT mint，可以交付所有权与出生基因组，但还不能交付可持续运行、可恢复的链上生命。建议在原计划前补创世数据发布与承诺，在 mint 后紧接最小生命记录闭环。保留现有金融隔离纪律；无须等金库、LLM、借贷、回购全部做完才让用户参与。

“真正上链”需要明确层级：

| 层级 | 可以证明什么 | 第一阶段建议 |
| --- | --- | --- |
| 身份、出生基因、所有权在链上 | 谁拥有哪个身份；出生字段未被改写 | 实现 |
| 数据包与初始状态承诺在链上 | 下载的数据是否等于出生时承诺的数据 | 实现，并发布真实数据 |
| 用户输入事件、会话授权、历史检查点在链上 | 谁提交了什么，先后顺序及历史承诺 | 紧接 mint 实现 |
| 所有连接、所有状态字节存于 BSC | 可从该链的数据重建全部材料 | 不作为首发前提 |
| 每步神经计算由合约执行或验证证明 | 状态转移符合约定程序 | 后续单独研究 |

哈希上链不等于数据上链；上链提交不等于计算正确；可重放不等于复原真实生物意识。推荐首发公开表述：“基于 MaleCNS 连接组的数字果蝇，身份与生命历史承诺在 BSC，模型运行及完整档案在链下，可独立重放。”

## 当前实物与核验范围

- 已有 Node HTTP 后端：`server/src/index.mjs`、`sessions/service.mjs`、`shared/graph-fs.mjs`。能加载连接组、推进会话、存盘与重放，不是需要从零建后端。
- 默认图是 `malecns-circuit`：1,400 节点、42,031 条边；浏览器和 Node 可以使用同一内核。
- 本机已有 `malecns-full`：161,839 节点、2,749,558 条边；graph.bin 为 22,643,836 字节，metadata.json 为 15,141,303 字节。它采用显著连接及 minWeight ≥ 10 筛选，不是原始完整 MaleCNS 图；不能用官方普查数替代实际运行规模。
- `.vercelignore` 排除 `server` 和 `public/data/malecns-full`；`vercel.json` 未配置 Node API 反代。当前仓库部署配置不能证明生产后端及大图已可用；外部独立部署与环境变量本次未核验。
- Soul 主网合约尚无源码；现有 `ImmortalFly.sol` 是 16 节点测试网原型。前端钱包模块仍限定 chainId 97。
- `official.json` 标记 IFS live、vault 为 null。本次未重新 RPC 核验税币、税收接收方与主网交易；它们是仓库清单事实。

本地核验：脑、表型测试 18 项通过；后端测试 8 项通过。后端 HTTP 测试首次受沙箱监听限制，放行后通过。对大图校验 metadata/graph/provenance 哈希，并运行中性输入 16 步及重放，结果一致；本机加载约 266ms、推进约 142ms。此结果不是活跃图吞吐、多人并发、持续运行或生物有效性的基准。

## 上线前的具体缺口

### 1. 后端恢复会改变同一只蝇的表型——已复现

`server/src/sessions/service.mjs:428` 的顶层成员档案不保存 genome；`:356` 的优先恢复分支也不恢复 genome。虽然嵌套 pitSnapshot 有 genome，这个分支未使用它。之后显示回退到当前 RNG 或缺省身份读出。

复现：使用真实 circuit 图，创建 seed=42 的会话，tick 一次、flush、重启服务。出生 seed=11355432，恢复后成员没有 genome；神经状态保持一致，但显示从“朱红眼 / 1 条条纹”变为“墨褐眼 / 2 条条纹”。

修复要求：出生记录独立持久化，恢复必须完整验证；旧档案优先读取已有出生记录，缺失时显式标识无法确定，不能静默拿当前 RNG 重造出生身份。增加跨进程恢复前后的 genomeHash、表型、谱系不变验收。

### 2. 会话默认 24 小时后删除，与永久历史目标冲突

`server/src/config.mjs:49` 设置 maxAge=24h；service 的启动恢复、sweep、读取路径都会删除超龄磁盘目录。tick 由客户端发起，关闭页面不等于后台继续生活。

修复要求：临时 guest 会话与已铸造 Soul 档案分开保留策略；热会话可以卸载，正式档案不得随缓存 TTL 删除。持久化事件使用原子写入或事务；归档、备份、恢复演练先于常驻运行。初版允许休眠，准确展示“已计算步数、最后检查点”，不伪称始终在线。

### 3. Soul / Genome / 创世根还没有形成统一身份链

`colony.mjs:35` 创建 genome 时未传 genesisId，保持零值；`kernel.mjs:104` 绑定创世记录时没有建立到已有出生 genome 的正式关联。实测会话有非零 genesisId，而成员 genome.genesisId 仍为零。

不同会话还重复使用 `colony-0` 等 soulId，而 service 用全局 soulId → sessionId Map，后建会话可覆盖前者的索引。这适合作为局部编号，不能作为公共链上身份。

修复要求：新链上身份使用 chainId + collection address + tokenId，Session/Branch 另行标识；先确定不可变创世根，再创建正式出生记录。旧 SIM 记录保留原语义，不就地重新哈希。

### 4. §19 的字段、哈希与升级叙述尚不足以直接写不可升级合约

- JS genome 含 schema、audit、soulId、genesisId、parentSouls、inheritBias；§19 合约列表没有完整对应。仅把现有 JSON SHA-256 换成 Solidity keccak256 会产生另一种承诺。
- `mutateRootOf` 是 xorshift32 展开，源码明确说明“形状像哈希”。它可作确定性表型素材，不能作密码学防篡改根。
- `inheritBias` 实际影响体型，JS/Solidity 对齐不能漏掉它。色值有浮点转换和舍入，也需固定测试向量或整数查表。
- 固定 1024 总供应、禁止升级、以后再加 breed：三者之间要提前设计。1024 应明确是 Gen0 上限还是整个集合上限；首版用外部谱系注册或后续新集合时，也须明确身份和亲代引用规则。
- 固定链上 decoder 与“全体再表达”应分开：保留出生版本 tokenURI；新客户端读出带版本标签，不让官网和 NFT 元数据悄悄不一致。

修复要求：写一页 schema/encoding 规范。保留现有 SIM v1，新链上编码必要时另起版本；发布跨语言测试向量，绑定创世根、schema、decoder 的精确版本与代码包指纹。展示标签不宜混进不可变身份哈希。现有 canonical SHA-256、EVM typed hash、CID 的关系必须明示。

### 5. 发行随机性与控制权需要明确

minter + nonce + 可知区块信息不能自动获得不可操纵随机性；批量地址、交易时机和区块参与者仍可能影响结果。免费 + 每钱包限制也不是防女巫。

建议：如果坚持不可预选出生性状，首版采用已核验可用的 VRF，或完整设计 commit/reveal（未来熵、揭示窗口、过期、放弃揭示与供应占用）。两者都会引入等待和额外复杂度。若优先单笔 mint，就公开披露种子可预测/可筛选，不再宣称公平随机，需在产品正文中作出选择。

当前后端 Bearer token 不证明 NFT 所有权。正式控制需钱包签名登录及 nonce/expiry，操作时核对链上 owner 与授权 epoch；转移后撤销旧 runner 的写入能力。ERC-721 市场 operator 授权不要默认等于脑状态控制权。

### 6. 交易提交、排序和恢复需具有一致语义

当前后端幂等缓存只在内存，磁盘元数据与档案分开直接覆盖。正式写入要有持久化去重、每个 Soul 的串行推进、崩溃恢复及不可覆盖的事件记录。链索引需处理确认深度与重组，不能把提交中交易当最终结果。

钱包模块 `findOwnedTokenIds` 在全历史查询失败后仅回看 40,000 区块，可能漏掉早期仍持有的 NFT。新入口应使用分段日志扫描或可从链重建的索引，并用 ownerOf 复核。

## 最小目标架构

### 数据与运行

1. **公共创世包**：源文件指纹、处理脚本版本、筛选规则、实际节点/边数、许可与署名、graph、metadata、provenance、runtime 精确代码包、模型参数、输入/输出编码、初始状态、重放样例。发布一个内容寻址 manifest；runtime 字符串版本名不足以固定实现。
2. **数据可用性**：先用对象存储/CDN + 独立备份；同时做 IPFS 多节点 pin 或其他长期归档。CID 不是托管保证，需下载巡检与存储预算。相同物种图共用一份，每只蝇只保存各自初值、输入与状态，不重复存图。
3. **Runner**：初期一个 Node 服务即可，后续重计算移入 Worker/独立进程。先做单只创世实例，再测多个实例；不要先建分布式神经元托管网络。
4. **档案库与链索引**：保存追加事件、检查点、用户授权与链确认状态；可由链事件和公开数据包重建。独立重放 CLI 不依赖运营 API。

连接组下载本身可由静态存储提供，无需专门数据库逐条查神经元；长期运行、用户授权、持久化历史、提交检查点则需要运行服务。后端可以是官方或第三方，用户应能替换运行器并恢复同一份状态。

### 合约职责（建议名称，尚未实现）

- **GenesisAnchor**：发布不可变 manifestHash、内容地址、graph/metadata/runtime/初始状态承诺及规模；可做独立小合约，也可合并为 Soul 的集合级 immutable 配置。发布权与实际发布者公开，不能把任何人注册的根都自动标为“官方创世”。
- **ImmortalSoul**：ERC-721，保存出生 Genome，明确关联创世根与 decoder，免费 + gas、无 burn、无用户资金池。出生时无需写入整张连接组。
- **LifeJournal**：独立的生命事件与检查点注册。最低约束是 tokenId、session/epoch、sequence、prevRoot、inputRoot、stateRoot、runtimeHash、archive 内容地址；owner/限权 runner 授权、撤销、防重复、防跳号。链上接受根只说明授权发布，首版另显示重放校验结果。

用户参与可先支持：mint、转移、开始/暂停会话、提交有上限的标准刺激、封存检查点。需要链上真实性的输入写入事件；高频神经细节按确定性区间归档后批量承诺。用户本地实验标 Branch，不争抢正式历史。公开创世参考个体与用户拥有的后代/实例分开授权，不能让任意访客改写创世主历史。

完整图写 BSC storage 的数量级：仅当前 22,643,836 字节 graph，按 32 字节槽首次非零写约 20,000 gas 粗算，约 **142 亿 gas**，尚不含 metadata、初始状态及后续运算。实际取决于编码、压缩和写法；这不是部署报价。事件/calldata/分片合约可以另作归档方案，但不自动赋予合约读取全图和验证全部计算的能力。首版更适合承诺 + 数据可用性 + 独立重放。

## 推荐实施顺序与验收

以下是单名熟悉项目工程师的粗略工作量，不含等待公共 RPC、存储开通、审计、VRF 集成与用户签名的时间；以验收而非日期决定上线。

| 批次 | 工作 | 粗估 | 完成标准 |
| --- | --- | --- | --- |
| A | 冻结出生编码、创世范围、1024 的含义；修复 Genome 恢复、身份碰撞、正式档案保留 | 1–2 天 | 两个独立进程恢复同一实例，genome/表型/历史一致；会话到期不删除正式档案 |
| B | 发布公共创世包，制作 GenesisAnchor + ImmortalSoul 与对齐测试 | 2–4 天 | 全新机器下载校验并重放；创世关联不可替换；NFT 元数据与 JS 测试向量一致 |
| C | BSC 97 端到端、前端 mint/持有列表/详情/回执，检查源码与部署参数 | 1–2 天 | mint、刷新、拒签、失败、换钱包、转移、到顶边界均正确；测试网与主网清单隔离 |
| D | BSC 56 身份首发 | 取决于验收 | 已验证源码和字节码、公开地址/部署回执、低额真实 mint/转移通过；此时只宣称身份上线 |
| E | Node 正式运行与 LifeJournal，真实刺激和连续检查点 | 3–5 天 | 关闭网页仍按所选策略运行/休眠；公开输入能重放；旧 owner/runner 失效；重组/重启不重复执行 |

身份首发粗估约 4–8 个工程日，生命记录闭环另约 3–5 日，发现问题应延后。完整活跃大图、多实例容量需要单独基准；不能拿中性输入冒烟结果承诺 1024 只持续运行。

第一版前台只突出四个动作：看创世来源 → mint 我的蝇 → 运行/刺激 → 看回执与恢复档案。每条信息标明 Chain confirmed、Runner reported、Replay checked 或 SIM。点“校验”应实际下载并复算，而非只打开区块浏览器。

## 产品正文建议修订点

1. §0 增加后端已实现但非正式永续服务的事实；列出实际部署的数据规模。
2. §12 把 P0 拆成创世发布、身份 mint、生命历史闭环三个验收；消除 P6 再出现 Soul NFT 的重复阶段歧义。
3. §19 补集合级 genesisRoot、出生编码、供应范围、随机机制与所有权转移后的控制权规则。仅 genome NFT 不足以回应“大脑上链”。
4. §16 “家族相似自动出现”缺乏保证：XOR/xorshift 不会天然保留可见亲代性状；若要相似性，应明确位点遗传与变异规则，并测试。当前可称可追溯谱系。
5. §6.2 的 min(collateral, profit, orders, budget) 会让没有历史订单/收益的新用户额度归零，并混合不同计量。后续按每类 Credit 分别定义资产单位、来源余额及占用规则；先不以这条纸面公式编写资金合约。
6. FindYourAgent、借贷/RWA、复杂繁衍、分布式托管、LLM 扩展不放进本轮上线关键路径。税收接收地址仍应独立核验并公开，不能猜一个地址填入 vault。
